=========================================================================
 COMANDOS DE DIAGNOSTICO E VALIDACAO
 Cisco IOS (roteadores/switches) + hosts (PCs/servidores)
=========================================================================

1. VALIDACAO RAPIDA (inicio da revisao)
-------------------------------------------------------------------------
No switch (SW-01 / SW-02):
  show vlan brief
    Lista as VLANs ativas e quais portas fisicas estao vinculadas a cada uma.

  show interfaces trunk
    Confirma a porta em modo trunk (802.1q) e as VLANs permitidas.

No roteador (RT-00 / RT-01 / RT-02):
  show ip interface brief
    Confirma se as interfaces fisicas e subinterfaces estao up/up.

Nos computadores:
  ping <gateway>
    Testa comunicacao com o gateway local.

  ping 192.168.3.10
    Testa alcance do servidor DNS da Matriz (quando ha rota).


2. COMUTADOR — DIAGNOSTICO DE CAMADA 2
-------------------------------------------------------------------------
show running-config
  Exibe a configuracao ativa na RAM. Revisar portas, VLANs e trunks.

show interfaces switchport
  Ex.: show interfaces gigabitEthernet 0/1 switchport
  Status detalhado da camada 2: modo (trunk/access), VLAN nativa, encapsulacao.

show interfaces status
  Tabela resumida: link (connected/notconnect), duplex, velocidade e VLAN.

show mac address-table dynamic
  Endereços MAC aprendidos dinamicamente por porta e VLAN.

show spanning-tree
  STP por VLAN: portas Forwarding vs Blocking (evita loops).

show interfaces counters
  Contadores de erros/colisoes por interface.


3. ROTEADOR — DIAGNOSTICO DE CAMADA 3 E ROTEAMENTO
-------------------------------------------------------------------------
show ip route
  Tabela de rotas: conectadas (C), locais (L), estaticas (S), padrao (S*).

show ip arp
  Tabela ARP: IP <-> MAC dos vizinhos e hosts.

show ip interface
  Ex.: show ip interface gigabitEthernet 0/0.5
  Detalhes L3 de interface/subinterface (MTU, broadcast, ACLs).

show ip dhcp binding
  Clientes DHCP atualmente vinculados (quando ha pools configurados).

show ip dhcp pool
  Resumo dos pools DHCP (rede, gateway, DNS, leases).

show ip nat translations
  Traducoes NAT ativas (importante validar no RT-00).

show ip nat statistics
  Contadores de NAT (inside/outside, overflow).

traceroute <destino>
  Caminho salto a salto ate o destino. Identifica onde o pacote para.


4. DEBUG EM TEMPO REAL (roteador/switch)
-------------------------------------------------------------------------
Atencao: em producao real use filtros. No Packet Tracer e seguro p/ aprendizado.

debug ip icmp
  Pacotes ping (echo request/reply) entrando e saindo do roteador.

debug ip packet
  Cabecalhos IP que passam pelo roteador (origem, destino, protocolo).

debug ip nat
  Eventos de traducao NAT (util no RT-00).

undebug all   (ou: un all)
  Obrigatorio apos qualquer debug — desativa todos os monitoramentos.


5. DISPOSITIVOS FINAIS (PCs e servidores)
-------------------------------------------------------------------------
arp -a
  IPs e MACs resolvidos na sub-rede (ou o MAC do gateway).

tracert <destino>
  Equivalente Windows do traceroute.

netstat -r
  Tabela de rotas do PC; confere a rota padrao (Default Gateway).

ipconfig /all
  IP, mascara, gateway, DNS e se o endereco veio de DHCP ou estatico.
  Confira se o DNS veio como 192.168.3.10 (padrao corporativo).

nslookup
  Testa resolucao DNS (ex.: nslookup servidor-matriz.local).


6. CENARIOS DE TESTE RECOMENDADOS
-------------------------------------------------------------------------
A) Filial -> Matriz (inter-VLAN / inter-sede)
   PC-01 (VLAN 1 filial) -> ping 192.168.3.10 (servidor)
   Esperado: sucesso via SW-01 -> RT-01 -> RT-00 -> RT-02 -> SW-02
   Se falhar: tracert 192.168.3.10 e debug ip icmp no caminho.

B) Matriz interna (VLAN 5 -> VLAN 8)
   PC-04 -> ping 192.168.8.1 (gateway TI) e host da VLAN 8
   Esperado: sucesso via SW-02 -> RT-02 (subinterfaces).

C) Acesso a Internet (requer Cloud/ISP no .pkt)
   PC qualquer -> ping 8.8.8.8 e tracert ate a borda
   Esperado: sai por RT-00 g0/0 com NAT (show ip nat translations).

D) Wi-Fi IoT — Matriz
   Device na SSID REDE_IOT_MATRIZ
   - Obtem IP 192.168.15.1xx (DHCP do WRT300N)
   - ping 192.168.15.1 (gateway WLAN)
   - ping 192.168.3.10 (DNS/servidor via WAN do roteador Wi-Fi)

E) Wi-Fi IoT — Filial
   Device na SSID REDE_IOT_FILIAL
   - Obtem IP 192.168.57.1xx (DHCP do WRT300N)
   - ping 192.168.57.1 (gateway WLAN)
   - ping 192.168.3.10 (DNS/servidor via WAN)

F) Validacao de trunk
   SW-01/SW-02: show interfaces trunk
   Esperado: modo trunk, VLANs permitidas exatamente as configuradas.

G) Validacao de DHCP
   PC da Matriz/Filial: ipconfig /all
   Esperado: IP a partir de .21, GW local, DNS 192.168.3.10

H) Validacao de ACLs e hardening
   RT-02# show access-lists
     ACL_IOT_IN e ACL_COLAB_IN presentes; contadores incrementam nos testes
   RT-02# show ip interface gigabitEthernet 0/0.10
     Linha: ip access-group ACL_IOT_IN in
   RT-01# show ip interface gigabitEthernet 0/0.10
     Linha: ip access-group ACL_FILIAL_IOT_IN in
   SW-02# show port-security
     Portas access com violation shutdown / sticky
   SW-02# show ip dhcp snooping
     Snooping ativo; g0/1 em trust
   Qualquer IOS: show run | include enable secret | banner | transport input
     Hardening presente (secret, banner, SSH)
   Ping IoT -> 192.168.8.1 (host TI)
     Esperado: FALHA (ACL nega)
   Ping IoT -> 192.168.3.10 (servidor)
     Esperado: SUCESSO (ACL permite)
   SSH admin@<IP do roteador>
     Esperado: login local com secret; Telnet recusado
     Senhas do lab (ver README.md / TESTES.md / Documentacao Tecnica.md):
       - login: admin / Senai@Admin2026
       - enable: Senai@Enable2026
